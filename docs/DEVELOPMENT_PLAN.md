# 蓝猫陪玩系统 · 开发计划

> 记录已讨论但暂缓实现的中长期方案。当前优先级：先继续开发其他功能与 BUG 修复；本文件中的方案后续按阶段拆任务开发、测试和灰度。

## 待开发：即时到账提现方案

### 背景与约束

- 业务定位：平台撮合/中介型业务，服务者为入驻个人，平台内部完成订单结算、冻结、扣款和提现。
- 订单来源不全是微信支付，且存在炸单负收益、保证金、罚单、设备租赁费、线下费用、退店释放/补扣等内部账务规则，因此不采用微信/支付宝订单分账作为主链路。
- 继续以平台内部钱包账本为资金结算主账：订单结算收益先进入冻结/可用余额，提现前统一完成冻结期、负余额冲抵、保证金、罚单、设备租赁、线下费用等校验。
- 当前规模参考：单人月收入平均约 6K-7K，最高约 1.5W，总月流水约 35W。
- 税务口径：服务者依法自行履行纳税义务；平台需保留交易、结算、支付、实名等数据，并预留依法报送、扣缴或代办申报的能力与条款空间。不要在系统和协议中表述为“工资/薪资/员工发薪”。

### 目标方案

采用“小额即时到账 + 人工兜底”的双/多通道提现：

1. 主通道：微信商家转账。
2. 备用通道：支付宝转账到支付宝账户。
3. 兜底通道：保留当前人工扫码提现。
4. 暂不接第三方代发、暂不接银行 API；大额或异常提现仍走人工复核。

### 自动打款额度策略

- 单笔自动打款上限：`2000`。
- 不允许系统自动拆单规避单笔上限；超过 `2000` 的提现申请进入人工复核。
- 建议配置项：
  - 单笔自动上限：默认 `2000`。
  - 新人首次自动上限：默认 `500` 或 `1000`。
  - 单人每日自动上限：默认 `5000`。
  - 单人每月自动上限：默认 `15000`。
  - 平台每日自动总额上限：先按 `30000-50000` 灰度配置。
- 命中以下任一条件时进入人工复核：
  - 单笔超过自动上限。
  - 单人日/月累计超过配置上限。
  - 微信/支付宝实名不一致。
  - 近期存在炸单负收益、负余额冲抵、罚单争议、退店异常、黑名单等风险。
  - 通道返回风控、失败或结果不明确。

### 提现状态机规划

后续数据库/接口需要支持提现通道和打款状态，不直接复用现有“审核通过=已完成”的简单状态。

建议字段：

- `withdrawChannel`
  - `MANUAL_QR`：人工扫码提现。
  - `WECHAT_TRANSFER`：微信商家转账。
  - `ALIPAY_TRANSFER`：支付宝转账。
- `transferStatus`
  - `NOT_STARTED`：未发起打款。
  - `PROCESSING`：通道处理中。
  - `WAIT_USER_CONFIRM`：等待用户确认收款。
  - `SUCCESS`：通道确认成功。
  - `FAILED`：通道确认失败。
  - `CANCELLED`：通道关单/撤销。
  - `MANUAL_FALLBACK`：已转人工处理。
- 通道单号与审计字段：
  - 平台出款单号：稳定幂等，不随重试变化。
  - 微信/支付宝转账单号。
  - 发起时间、完成时间、失败原因、原始回调/查单摘要。

### 核心流程

```text
服务者申请提现
  ↓
钱包提现前校验
  - 收益冻结期
  - 可用余额
  - 提现次数
  - 首次提现规则
  - 保证金补扣
  - 罚单/设备租赁/线下费用
  - 负余额冲抵
  ↓
创建提现申请并预扣冻结
  ↓
后台审核
  ↓
选择/自动路由打款通道
  ├─ 微信自动打款
  ├─ 支付宝自动打款
  └─ 人工扫码兜底
  ↓
回调或查单确认结果
  ├─ SUCCESS：提现完成，扣减提现冻结
  ├─ FAILED/CANCELLED：允许转人工或驳回
  └─ PROCESSING/WAIT_USER_CONFIRM：保留冻结，定时查单
```

### 幂等与资金安全要求

- 自动打款“受理成功”不等于“到账成功”，必须以回调或查单最终态确认。
- 接口超时或结果不明确时，不允许换新单号重复发起；必须使用原平台出款单号查单。
- 自动打款成功前，不得提前把提现单最终置为成功。
- 自动打款失败后，提现冻结仍应保持可追踪状态；只能通过“转人工处理”或“驳回”进入终态。
- 驳回仍沿用当前规则：释放提现冻结回可用余额，可用余额允许仍为负，用于冲抵线下费用、罚单、设备租赁等欠款。
- 审核通过仍必须保持严格余额桶校验，负余额/异常余额不能通过自动打款。
- 历史异常清理场景允许“直接废除”提现申请：若账户已清零且冻结流水已冲正，不再二次改动账户余额，只将残留提现申请置为 `CANCELED`；若仍存在提现冻结，则废除时同步释放冻结。

### 用户绑定与实名要求

- 微信自动打款前置：
  - 服务者绑定微信 `openid`。
  - `openid` 必须属于商户号绑定的 `appid`。
  - 支持微信商家转账用户确认/免确认授权模式时，按实际产品能力接入。
- 支付宝自动打款前置：
  - 服务者绑定支付宝账号或 `user_id`。
  - 支付宝实名姓名与平台实名一致。
- 自动打款强制要求：收款账户实名与平台实名一致；不一致进入人工处理或禁止自动打款。

### 管理端功能规划

- 提现审批页：
  - 展示提现通道、自动打款状态、通道单号、失败原因。
  - 支持“审核并自动打款”“转人工处理”“查询通道状态”“驳回”。
  - 支持“直接废除”历史异常残留提现申请，用于账户清零/冻结冲正后仍残留申请单的生产数据修复。
  - 超额/异常单提示人工复核原因。
- 提现记录页：
  - 支持按通道、打款状态、时间筛选。
  - 支持对未终态异常提现申请执行“直接废除”。
  - 支持导出通道单号、平台单号、到账时间、失败原因。
- 系统配置：
  - 自动打款开关。
  - 微信/支付宝通道开关。
  - 单笔/日/月/新人限额。
  - 平台每日自动打款总额上限。
  - 风控命中后是否允许自动转人工。

### 测试计划

开发时至少覆盖：

1. 单笔 `<=2000` 且资料完整，自动打款进入处理中并最终成功。
2. 单笔 `>2000`，不能自动打款，进入人工复核。
3. 新人首次提现超过新人上限，进入人工复核。
4. 单人日/月累计超过配置上限，进入人工复核。
5. 微信/支付宝实名不一致，拒绝自动打款。
6. 通道受理成功但未最终到账，提现冻结不释放。
7. 通道失败后可转人工。
8. 通道失败后可驳回，驳回释放冻结并允许可用余额仍为负。
9. 接口超时后使用原单号查单，不重复创建新通道单。
10. 并发审核/重复回调/重复查单保持幂等，不重复扣除提现冻结。

### 暂缓事项

- 暂不接微信/支付宝订单分账作为主链路。
- 暂不接银行 API/银企直联。
- 暂不接第三方代发或灵活用工平台。
- 暂不取消当前人工扫码提现。
