# 直播挑战赛开发计划

| 阶段 | 验收范围 | 估算 |
| --- | --- | --- |
| 1. 数据与规则 | 赛事、时段、门票、名单配额、两局成绩结构及迁移 SQL。验证计分、排名和随机配额。 | 1–2 人日 |
| 2. 订单与资格 | 客服售票、会员提醒、并发限购限量、40 张开放预约、70 张封顶、全额退款退赛、首次有效成绩核销、固定服务费结算与评价。 | 3–5 人日 |
| 3. 预约和后台赛事运营 | 预约改约、身份资料、缺席人工候补、签到排场、配置当日候选人、录分与更正、发布及锁榜。 | 3–4 人日 |
| 4. 主播和直播页面 | 主播控制、独立观众投屏、转盘动画与自动绑定、售票进度、实时同步、公开字段验证。 | 3–5 人日 |
| 5. 小程序 | 赛事详情、预约与改约、赛前提醒、实时参赛状态、当日服务者、榜单和我的排名。 | 2–4 人日 |
| 6. 联调与验收 | 用户执行本地迁移后，覆盖售票到结算、退款与录分冲突、抽取重试和名次变化。核验直播大屏与小程序常用尺寸。 | 2–3 人日 |

## 开发与验收口径

- 首期客服售票。每会员一张有效票，无历史消费时提示客服。订单取消或超时释放占位。赛事期间配置日期、每日直播时段和容量。
- 小程序预约带入微信昵称及手机号，收集游戏 ID、游戏昵称、段位，可选参赛昵称。缺席候补由小助理人工处理，首局实际开打前可改约一次。
- 主播控制页显示当前及下一位的完整游戏 ID 和两种昵称。观众投屏显示两种昵称，公开数据排除游戏 ID 和联系方式。主播确认上场后才可抽取。转盘从当日候选名单按保底及上限抽取，自动锁定到门票。同一服务者陪同两局。主播页、投屏和小程序实时同步参赛状态。结束后关闭公开服务者名单入口。
- 一杀一分，每局最高 6 分。总榜按总分、单局最高原始击杀数、最短首杀耗时、达成该首杀的实际时刻比较。双方无击杀记录时按参赛时间先后排序，暂以主播确认上场时间为参赛时间。总分为 0 不排名。每局发布后更新名次变化，展示单局最高击杀及最快首杀榜，赛后锁榜并人工发奖。
- 首次有效成绩保存即核销，0 分也核销。已核销门票不可退款。尚未核销时按现有退款条件处理，开打后同样适用。全额退款成功后退出有效名单和队列，释放库存及已占席位。第一局完成后第二局缺席按弃权计 0 分，整票确认履约并结算一次固定服务费。
- 设计重点是转盘、投屏、售票进度和小程序页面。主播控制应便于直播操作，内部运营页面沿用后台组件。
- 每次反馈按已完成、待验证及剩余阶段人日更新。估算含现场流程联调，根据实际订单接入和 UI 验收结果调整。

## 订单接入进度

- 客服可通过订单表单选择关联赛事的项目售票。接口要求绑定会员，店内服务者账号禁止参赛，无已完成消费订单时只提示。已收款的线下订单直接生成参赛资格。收钱吧保留支付结果和取消回调接入，当前收款码入口由现有系统暂停。储值预占属于未实际扣款，首期赛事售票暂用线下确认收款。
- 第 40 张有效已付款票记录预约开放时间。待支付票占用限购和库存，但不计入开放门槛。上限最多 70 张。
- 录分 API 仅允许参赛中或统计中的有效门票录分。保存有效成绩时同事务核销。全额退款成功后释放有效资格，待确认的线下退款以确认成功为准。下一阶段需要接入赛事配置、现场状态操作和录分表单。

## 赛事配置、预约与排场进度

- 后台在「推广运营 → 直播挑战赛」提供赛事创建、商品搜索、直播时段、容量、发布、每日转盘名单与配额、当日签到和排场。缺席及候补由小助理操作。
- 小程序预约 API 已接入，校验持票人、预约开放、时段容量、改约次数与退款状态。小程序页面和提醒仍待实现。
- 后续先接主播确认上场、抽签绑定、完赛与成绩发布，再联调录分页面、榜单和固定结算。直播投屏和小程序仍按独立设计验收。

## 直播控场进度

- 主播控制台支持确认下一位上场、抽取并锁定服务者、记录首局开打和转入成绩统计。每日配额可根据缺席后的抽取次数调整，保留已锁定人员和次数。
- 独立观众投屏与售票视图已接入，公开接口排除游戏 ID 和联系方式。两个页面以约 1.5 秒轮询同步，投屏适配宽屏与窄屏。
- 后续接入逐局发布、锁榜和投屏榜单，再联调小程序与订单结算。动画和公开路由仍需浏览器实操验收。

## 录分与榜单进度

- 后台已支持逐局录分、第二局弃权、发布、更正后重发，以及核对待处理成绩后锁榜。更正保存时保留上次公开成绩，重发后更新排名。
- 投屏可切换总榜、单局击杀榜和最快首杀榜。总榜标记新上榜及本次发布导致的名次变化。
- 新增成绩发布快照迁移 SQL，待本地迁移后与双屏和小程序联调。

## 小程序进度

- 门票订单详情新增赛事入口。赛事页展示预约和一次改约、参赛状态、出场顺序、已发布的成绩、今日服务者和三类榜单。只有持票会员可读取对应的个人门票资料。
- 已复用订单进度订阅授权和预约、改约成功通知。定时赛前提醒、真机确认订阅到达和完整订单回归待做。

## 整票履约与结算进度

- 两局结果均发布后，后台可确认整票履约。第二局弃权仍按赛事配置的每票固定服务费结算一次。以转盘绑定的服务者作为结算对象，沿用现有钱包冻结、业绩财务回写和订单完成状态。
- 订单行锁串行化重复确认。已完成的订单返回原结算批次。常规订单重算入口拦截赛事票，保留现有结算基数检查。
- 本地迁移后需要验证实际订单、钱包流水及重复并发请求。剩余定时赛前提醒和端到端联调。

## 赛前提醒进度

- 每分钟扫描一次，给距离预约时段开场一小时内的有效预约创建站内消息，并尝试通过已有订单进度模板发送微信提醒。改约后按新时段重新计时。
- 提醒标记与站内消息同事务写入。微信授权、模板配置及真机送达留待联调验证。

## 本地验收进度

- 在本机 bluecat_dev 用事务回滚方式验证真实 MySQL 的售票规则、预约容量、赛前提醒去重、转盘、公开字段、逐局发布、零分核销及锁榜，测试记录已回滚。
- 录分校验增加首局开打记录，避免在选手刚上场时误核销。
- 仍需用正常客服下单和退款入口完成浏览器联调，检查真实并发结算与钱包流水，并做微信真机和大屏视觉验收。

- 本地通过现有客服 HTTP 接口实际创建门票、确认线下全额退款及录分。核销后退款返回 400，无退款流水。已排场门票全额退款后移出名单并释放资格。
- 真实钱包写入联调发现并修复赛事结单未加载完赛派单记录的问题。第二局弃权时，4 个并发结算请求只产生一条 ¥36.50 结算、一条钱包流水及一次余额增加。测试数据已清理。
- Chrome 双窗口已验证已登录主播页面与匿名投屏、转盘抽取同步、窄屏售票视图、成绩发布和榜单同步。接入 IDEA 3001 调试服务时，后台用 `BLUECAT_LOCAL_API_URL=http://127.0.0.1:3001 npm run start:dev` 启动。修复超级管理员访问赛事页面的权限判断。
- 剩余微信开发者工具/真机页面、订阅提醒实际送达和最终现场尺寸复核。
